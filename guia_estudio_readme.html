Documento de Especificación de Requisitos de Software (ERS)

Proyecto: FitnessChile - Plataforma Web E-Commerce y Entrenamiento Deportivo

1. Introducción

En esta sección se proporciona una introducción completa al documento de Especificación de Requisitos de Software (ERS) para el sistema FitnessChile, definiendo las bases funcionales, alcance y marco técnico que rige su desarrollo colaborativo.

1.1. Propósito

El propósito del presente documento es definir de manera formal, rigurosa y exhaustiva los requerimientos funcionales y no funcionales que debe satisfacer la plataforma web de FitnessChile.

Este documento va dirigido a:

  • Equipo de Desarrollo Fullstack: Para guiar la arquitectura, maquetación semántica, diseño responsivo y lógica de validación del cliente.
  • Comité Evaluador y Docente: Como evidencia documental del cumplimiento de los estándares de ingeniería de software, accesibilidad, estándares web (W3C) y metodologías colaborativas en Git.
  • Stakeholders y Administradores del Negocio (FitnessChile SpA): Para alinear las expectativas comerciales, alcances de las entregas y futuras integraciones de pasarelas de pago y módulos de inventario.

1.2. Ámbito del Sistema

• Nombre del Sistema

El sistema se denomina formalmente "FitnessChile Web Platform & E-Commerce Core" (Versión 1.0).

• Lo que el Sistema Hará:

  • Presentación de Marca y Contenido Multimedia: Exponer la identidad de la tienda mediante Hero Banner dinámico con slider automatizado y secciones informativas. Incluye reproductores de video responsivos (16:9) sobre técnica y preparación física.
  • Catálogo de Productos y Navegación Interconectada: Desplegar la cuadrícula de 8 productos destacados con precios en CLP ($) y filtrado interactivo por categorías sin recargar la página. Navegación fluida entre index.html, productos.html, nosotros.html, blog.html y contacto.html.
  • Formulario de Contacto y Validación en JS: Formulario accesible con etiquetas <label for>, autocompletado y validaciones preventivas en tiempo real con mensajes contextuales específicos bajo cada campo (correo RFC, teléfono chileno de 9 dígitos, etc.).
  • Newsletter y Notificaciones Toast: Suscripción por correo electrónico y confirmaciones emergentes no invasivas.

• Lo que el Sistema NO Hará (Fase 1):

  • No procesará pagos bancarios reales en vivo: El botón de carrito muestra estado informativo ([Fase 1]) hasta la conexión con Transbank / Webpay Plus en fase 2.
  • No gestionará autenticación de usuarios en base de datos: El módulo de contraseñas y login fue resguardado en la carpeta proximos_cambios/ para la fase de backend.
  • No controlará inventario ERP en tiempo real.
  • No gestionará envíos internacionales (restringido a Chile).

• Beneficios, Objetivos y Metas:

  • Beneficios: Vitrina digital 24/7 accesible desde cualquier pantalla con tiempos de carga mínimos al usar tecnologías nativas (HTML5, CSS3, JS Vanilla).
  • Objetivos: Cumplir 100% con los estándares W3C, diseño responsivo y flujo de control de versiones con Git.
  • Metas: Cuadrícula de 8 productos destacables, validación en cliente menor a 100ms y base modular para fases 2 y 3.

1.3. Definiciones, Acrónimos y Abreviaturas

  • ERS: Especificación de Requerimientos de Software (IEEE 830).
  • Comanda / Orden de Pedido: Detalle del pedido de productos o menú solicitado por el cliente para su despacho o retiro.
  • HTML5: Estándar de etiquetado semántico (header, nav, main, section, article, footer).
  • CSS3: Hojas de estilo en cascada con variables (:root), Grid, Flexbox y media queries.
  • DOM: Representación en árbol de los elementos HTML manipulables mediante JavaScript.
  • Módulo 11: Algoritmo para verificar el dígito verificador del RUT chileno.
  • Toast: Notificación emergente temporal en pantalla.

1.5. Visión General del Documento

El documento consta de un área de definición del negocio, un área de especificación de requisitos (HTML5 semántico, CSS3 externo y validación de formularios en JS), y proporciona el detalle de los requerimientos a través de formularios de casos de uso como anexos.

2. Requisitos Específicos

  • REQ-01 (Semántica HTML5): Uso de etiquetas semánticas estándar sin abusar de div.
  • REQ-02 (Páginas Interconectadas): 5 páginas HTML físicas enlazadas de manera coherente.
  • REQ-03 (Video Embebido Responsivo): Video con proporción 16:9 adaptable a cualquier dispositivo.
  • REQ-04 (Hoja de Estilos Única): Todo el sitio utiliza css/style.css.
  • REQ-05 a REQ-11 (Validación en JS): Etiquetas asociadas, autocompletar, validación de correo RFC, teléfono de 9 dígitos, longitud de mensaje mínima de 15 caracteres y mensajes de error contextuales.
  • REQ-12 a REQ-14 (Git Colaborativo): Ramas por integrante y commits semánticos.

3. Anexos: Casos de Uso del Sistema

Caso de Uso CU-01: Filtrado de Catálogo de Productos

Actor: Cliente / Visitante.
Flujo: El usuario ingresa a productos.html, selecciona una categoría (ej: Fuerza), el script en js/app.js filtra los productos sin recargar la página y muestra las especificaciones técnicas en un toast al hacer clic.

Caso de Uso CU-02: Envío de Consulta con Validación de Formulario

Actor: Cliente / Visitante.
Flujo: El usuario completa el formulario en contacto.html. Si algún dato es erróneo, se muestra el mensaje específico en rojo bajo el campo. Si todos los datos son válidos, previene el refresco, limpia los campos y notifica con un Toast de confirmación.
